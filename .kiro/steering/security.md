# セキュリティ・不変条件

## セキュリティ必須条件
- S3 のパブリックアクセスを許可しない。フロントのみ CloudFront から OAC で参照させる。
- 原本・サムネイル・メタデータは公開しない。APIは必ず認証済みユーザーIDと所有者／グループメンバーを照合する。
- クライアントの `ownerId` / `albumId` / `mediaId` 等を信用しない。取得した正本JSONに基づき権限判定する。
- グループの認可は API 側の正本データで判定する。フロント表示の非表示だけで権限を守らない。
- LINE の Channel Secret や Cookie 署名鍵などをフロントエンドに送らない。Gitにも置かない。
- OIDC の署名検証・state・nonce・PKCE・token の期限／audience／issuer 検証を省略しない。
- セッション Cookie は Secure / HttpOnly / SameSite=Lax を設定。変更系APIには CSRF 対策を実装する。
- S3 署名付きURLは短命（原本URLは暫定5分）とし、権限確認を省略して発行しない。
- `trash/` を閲覧用APIや発行対象のプレフィックスとして許可しない。
- 入力文字列の XSS／HTML注入対策を実施。ファイル種別は拡張子だけで判断せず、実サイズとMIME/マジックバイトを検証する。
- Lambda や CDK に `s3:*` や `*` リソースなどの過剰権限を安易に付与しない。
- APIはエラーを機械可読な形式で返し、画面には利用者向けの説明を出す。
- 時刻は UTC ISO 8601、ID は UUID など衝突しにくい値を使う。

## S3ごみ箱の不変条件
- コピー完了を検証する前に原本を削除してはいけない。
- `deleting` 以降のメディアを通常一覧・署名付きURL発行結果から除外する。
- 削除は安全にリトライできること（実行途中の再実行／二重クリック対応）。冪等に成功させる。
- `trash/` の Lifecycle のみが期限削除を行い、`originals/` と `previews/` は対象外。
- 削除期間は暫定30日。変更可能な CDK 設定とする。
- アルバム表紙が削除される場合、残存メディアを選ぶかプレースホルダに戻す。
- 削除時の移動キー（コピー元/先）と削除日時をJSONに保存する（将来の復元用）。

## コメントの不変条件
- スレッド階層は root + children の2階層のみ。子への返信も root 直下に格納する。
- 親削除時は本文のみ消して墓標（deletedAt 付与）を残し、子を維持する。
- 子削除時に他のコメントを変更・削除しない。
- メディアのコメントにも対象アルバムの所有者権限を適用する。
- メディアがごみ箱に入った後は、そのメディアのコメントも一般画面に表示しない。

## 状態整合性
- S3 JSON 更新には競合制御（ETag条件付き書き込み）を用いる。
- S3イベントと削除処理には冪等性を持たせる（重複・順序不定に耐える）。
